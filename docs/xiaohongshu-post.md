## 正文

DeepSeek Harness（8月13日开源，几天破10万星）有个设计问题，实测会让模型多花 3 倍请求：

它的 bash 工具提示词告诉模型："检查每个退出码，失败就先调查再继续"。
但 `grep` 搜不到东西时退出码是 1 —— **这是正常结果，不是失败**。
模型看到 `[exit code: 1]`，按提示词去"调查失败"，于是反复验证一个本来就正常的结果。

社区有人实测：同一个任务，dsh 发出 61 次请求 vs 竞品 32 次；成本 $0.17 vs $0.05；输入 token 290 万 vs 55 万。

我写了一个插件 `dsh-benign-exit`：
- 在**结果层**确定性改写模型看到的内容——grep 无匹配时，模型看到的不再是光秃秃的 `[exit code: 1]`，而是：
  ```
  (benign: no matching lines — expected, not a failure)
  [exit code: 1]
  ```
- 在**提示词层**补一段"良性退出码词典"（grep/diff/test/which/jq/git diff 各自的正常退出码含义）。

诚实说明：
- ✅ 已验证：在真实 harness 机制里跑通了 36 个单测 + 10 个集成测试 + 6 个真实 bash 端到端测试（真实跑 grep/git 进程），并确认不影响 UI 退出码显示。
- ⚠️ 还没做：真实 LLM 对拍（需要 API key），所以**不声称省了多少成本**。上面的 61 vs 32 是社区数据，不是我的。
