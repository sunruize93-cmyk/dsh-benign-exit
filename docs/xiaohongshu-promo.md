## 二、正文草稿(大白话版,约 300 字)

**开头钩子(踩坑场景):**

> 最近 DeepSeek Harness 爆火,几万 star 那种。但我用它的时候发现一个很气人的事:让它搜"某个函数存不存在",它搜不到之后,还会一遍一遍反复搜、反复验证,账单蹭蹭涨。
>
> 我扒了下它的提示词,发现问题在这句:"检查每个退出码,遇到失败先调查再继续。"
>
> 问题是:`grep` 搜不到东西,返回的退出码是 **1** —— 这是**正常结果**,不是报错。模型按指令把"没搜到"当成了"失败",于是自我强化式地空转。

**修复原理(一句话):**

> 我写了个插件,在模型看到的结果上**直接注明"这个退出码是正常的"**,模型读到就不再空转。(真实运行里模型会复述:"harness wrapper 标注了这个退出码是正常的"——它真的读懂了。)

**实测数据(可查证):**

> 2026-08-17,用 deepseek-v4-flash 真跑了 before/after,只差开不开这个插件:
> - 让模型反复用 shell 验证"东西不存在"的任务:**57 万 token → 36 万,省约 38%**,耗时也省 1/4
> - 全部任务合计(24 次运行):113 万 → 90 万,**省约 20%**
>
> 原始数据全在 GitHub 上,可以自己复现。

**诚实边界(赢信任):**

> 说清楚:这组数字来自专门设计的"验证类"任务,是这套机制的天花板,不是人均值。轻量任务基本没差别。装不装看你任务里有多少"验证东西在不在"的活。

**收尾:**

> 开源免费,MIT。装一行:`dsh plugin add dsh-benign-exit`
> 项目:github.com/sunruize93-cmyk/dsh-benign-exit
> 评论区欢迎拍砖——你见过哪种"agent 空转"最无语?
